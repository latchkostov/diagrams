## Message choices follow playback

Message choices, Carries, hover details, agent descriptions and Checks now share playback's forwarding decisions with capacity analysis. Async store change feeds carry their real output types, broker consumers ignore fan-out shares, and request tables and filters select the same routes. Saved simulations contribute their own traffic types and setup overrides without combining unrelated run configurations.

## Verified loop fixes

Filter and rename candidates are checked against the whole graph's cyclic typed transitions. A rename that merges existing loops into a new loop is rejected. Verification preserves non-loop traffic in free play and each saved simulation, including its setup overrides. Runtime property edits require temporal proof and therefore receive no automatic fix from this static verifier.

All loop findings share indexes, cached candidate analyses, a 24-candidate limit and one work/allocation budget. Findings remain visible when optional fix verification runs out of budget. Applying a fix regenerates only that finding's candidates, while checking safety across the whole graph. Traversal keys intern type names. Moving or selecting diagram elements reuses the same propagation result; leaving an edge suspends its reader.

## One forwarding model for detection, choices and fixes

Loop detection, propagation and fix verification now run on the forwarding semantics playback uses, end to end:

- Saved simulations are configured by the helper playback uses (`simulationSetup`, beside the routes in `src/sim/topology.ts`, so it adds no chunk): connection overrides carry only waiting-call settings, as in playback, and node patches apply as the engine applies them. A candidate edits the base diagram first and every saved run's overrides are applied after it, so verification proves what the edited diagram plays.
- Each run yields a typed state graph whose states keep the request route, the unaddressed-request flag and injection, as playback keeps them with a message. Verification compares transitions, never edge/type pairs: legitimate traffic is every transition reachable from the run's inputs without going round a loop, and a candidate must keep all of it, add no cyclic transition and leave none of the finding's loops. A finding is every loop reported at its node, so a fix that stops one type while another keeps looping there is not offered. A rename may carry its new name only for what crossed its edge into those loops.
- The analysis asks playback's `forwardingShare` for the role gate and share. One budget per analysis covers vocabulary, compiled type filters (wildcards included), each pattern check, request filters, route tables, states, transitions and Tarjan's pass. Type filters (`src/model/typeFilter.ts`, outside playback chunks) compile once per analysis into exact names and wildcard prefixes grouped by length, with results memoized per connection and type; a property test proves them identical to playback's `acceptsType`. Over budget, the analysis reports itself incomplete: the warning stays, without a fix. Verification reuses the Check's own analysis as its baseline.
- Readers on the canvas compare element references instead of serializing the graph. Pan and zoom keep React Flow's arrays (one comparison); dragging replaces nodes but not their data (a reference comparison per element). The inspector's cache compares the same fields of up to four recent snapshots.
- Agent descriptions spend a 100,000-character budget on type names as rows are written, reporting `arrivingTypesOmitted` / `carriedTypesOmitted` past it, and text output counts lines past its limit without building them.

## Keyboard editing

Removing a processor rule, including choosing Unchanged, sends focus through the canvas focus controller to a surviving rule or Add a rule. Rules keep their incoming-type identity, so a removed row's draft cannot move to another rule. Changing a rule's incoming type, from its menu or a new-type draft, continues at that rule's "When it receives" control after the commit (focus policy row I5). Deselecting a filter type that nothing upstream sends moves focus to a neighbouring chip, or Add a type. New-type inputs focus when mounted, without stealing focus during unrelated edits. Keyboard-focused flow edges show a readable tooltip associated with their wrapper through aria-describedby.
