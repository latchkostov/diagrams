## Parallel contributions without shared-log conflicts (2026-10-17)

- Release notes and design reviews now use one dated fragment per PR; the old logs remain linked as frozen
  history. `pnpm notes` builds the complete view on demand, including in offline packages. Backlog findings
  use independent files too; UX principles remain the shared behavior contract.
- `pnpm regen` refreshes committed outputs. Public schemas are generated by Vite in dev/build and no longer
  tracked. The plugin uses Claude Code's commit tracking, removing competing patch bumps from PRs.
- `pnpm sync` fetches/rebases onto master, regenerates safe conflicts and unions distinct English keys.
  It preserves authored reference prose, stops on competing edits, and leaves parity goldens for review.
- No app behavior, controls, UI text or parity goldens change. No benchmarks or full e2e gates run for this
  contributor-tooling change; CI retains the full suite. Details and the local proof: [parallel work](../PARALLEL-WORK.md).
