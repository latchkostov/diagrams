## Faster Live refresh and panel close

Live now refreshes geometry only when paths or layout change, reuses length and point samples
by path data, and reads marching styles only when their inputs change, sharing identical appearances. Geometry and style
invalidation are separate; repeated identical DOM attributes and changing badge text do not
invalidate the scene. March revisions replace full-edge JSON comparisons. CSS supplies the
same target opacity to SVG and canvas without enumerating animations per edge.

The decorator collects its elements in one selector pass before writing attributes. Trace
obstacle reads are also combined. Hidden Overview badge updates no longer remeasure every
card. Closing Inputs & capacity no longer repeatedly measures hidden
Overview labels or builds a whole-label collision list for every hidden edge; visible-label
resets are batched before measurements. Focus and Follow retain their placement rules.

The exported viewer specializes its existing main-thread renderer at build time, removing
unreachable worker code to keep the viewer smaller. No budgets, reserve, ZIP cap, benchmark
baselines or parity goldens are raised or re-recorded. This is a performance change, with no
new controls or simulation behavior.

## Evidence and verification

The benchmark comparison uses the deterministic pipeline at 100 and 500 nodes, production
E2E builds, Chromium, quick mode and the harness's default 2× CPU throttle on the same Windows
machine. Timings are observations rather than pass/fail budgets. The base is `650e032ad`.
Worker ×1 supplies frame time and particle FPS; panel close uses worker ×10 with the heat map.
React renders are counted per second on the names-preserving production build.

Operation-count regressions cover 100 unchanged ticks at 64 and 512 edges with zero selector,
geometry, computed-style, serialization or node-map reads; one changed edge style; geometry,
zoom, theme, remount and visibility changes; and one selector pass per decoration publish.
Browser regressions require zero settled card measurements across ten Live publishes and at
most one measurement per edge label for the deliberate camera fit during panel close at 100
and 500 nodes. Reverting the fixes makes the regression tests fail; the original panel close
read 559 and 4,431 label rectangles respectively in the regression run.

At 500 nodes, React commits/second rise from 5.3 to 7.0 as Live publishes more frequently;
renders/commit fall from 417.2 to 408.6. At 100 nodes both remain 7.7 and 91 respectively.
The small diagram's frame and close observations are essentially unchanged, with slight
increases. These local quick runs are not an isolated-runner comparison: another checkout's
full gate began during the last part of the head run. Use the same-job Actions comparison
for the controlled follow-up; no benchmark baseline is changed.

The viewer template shrinks from 1,886,153 to 1,878,413 raw bytes, or 623,266 to 620,859 bytes
with gzip. The generated skill ZIP shrinks from 832,697 to 830,355 bytes, below the unchanged
835,000-byte cap. Parity golden files are unchanged. The targeted Linux gate exited 75
because all 12 shared worker slots were occupied; required repeats, parity, reserve and
production size verification therefore defer to PR CI under the documented busy-gate rule.
