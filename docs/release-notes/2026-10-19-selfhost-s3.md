## Self-hosted relay rooms

Builds can choose `VITE_COLLAB=off|public|server`. The existing `VITE_ENABLE_COLLAB=1` still selects
public matchmaking. Server builds use only the encrypted WebSocket relay, with no WebRTC, STUN or
fallback to public infrastructure. Rooms work independently of share links and remain loaded on demand.

The relay defaults to `collab/v1` under the served base. An optional absolute `VITE_COLLAB_SERVER`
selects a `wss://` endpoint; `headers:self-host --collab-server <url>` allows exactly its origin in
the app's connect-src. Same-origin relays need only the existing `'self'` policy.

Start and join consent name the relay host and its IP-address/room-presence visibility. Room-full and
server-unreachable failures explain the cause and retain Retry and the local file-copy fallback.
Private diagrams remain blocked, with no privacy escape in the room dialog or server-mode Share.
Public matchmaking wording and the empty-tracker explanation are unchanged.

## Verification and scope

Relay conformance uses the real in-process server and captures encrypted traffic. The browser variant
uses two contexts and a real relay behind a preview origin, verifies two-way edits, no WebRTC,
same-origin CSP, full/unreachable failures and blocked Private diagrams. Production-build tests guard
the transport split and lazy startup. The queued HEAD/GET compression-selection and session-frame
boundary regressions were already present in the S2 baseline and remain covered.

Only `node/i18n/catalogs.json` changes intentionally: four new English messages for relay start/join
consent and its two failure states increase catalog message/fallback counts and change the collaboration
namespace hash. Existing translated messages and `node/i18n/messages.json` are unchanged. No diagram,
simulation, export, layout or rendering golden changes.

Container packaging, Helm, runtime configuration and relay enforcement of signed roles remain for
their separate steps.
