## Sampling: breakers keep the work budget

A circuit breaker no longer lowers the automatic sampling scale. Before, any breaker on a Request connection capped the whole diagram's scale at `minimumCalls / 4` (5 with the defaults), whatever the traffic: at 50,000 requests/s a gateway breaker raised sampled input from 50 to 10,000 dots/s, and at 100,000 requests/s it tripped the engine's 10,000 dots/s source limit, so continuous traffic stopped. Unrelated branches, disabled breakers and breakers no traffic reaches paid the same price. `autoScale` now returns the entry-rate budget's scale (about 60 entry dots/s) with or without breakers.

Breaker resolution is handled locally instead. Its windows already count real requests, so opening and closing don't depend on the scale. A half-open breaker now narrows a dot to its remaining test calls (the throttle split, `throttleSplit`): the connection carries exactly `halfOpenCalls` real requests to the callee, and the rest of that dot fails fast at the same instant, as scale 1 short-circuits the rest of a burst. The narrowed branch sizes its own retries, successes and budget decisions. Before, the whole dot went through as a test, overshooting by up to one dot per test batch, which added up over repeated failed tests.

Evidence (same-arrivals I1, `src/sim/breaker.sampling.test.ts`): a gateway calling a database-like service at 1,500/s (scale 50) and 3,600/s (scale 100), for an outage, repeated failed tests, retries, slow calls and an overloaded callee. Breaker transitions match scale 1 within one cohort interval, half-open batches never send more than scale 1, the connection's short-circuit, timeout, retry, success, attempt and failure counters match scale 1, and every node and connection stays within the I1 bound. One residual remains (see the [backlog](../backlog/2026-10-23-breaker-probe-caller-outcome.md)).
