# Languages (i18n)

Live Diagrams speaks 38 languages: English, the source, and 37 machine-translated ones (the operating-system set:
every Windows base language, plus Indonesian, Vietnamese and Hindi). Why these, how terms are chosen and what was
weighed: [`docs/research/i18n.md`](research/i18n.md). This page is how to work with it.

- People choose with **View ▸ Language…** or Ctrl+K **Language…**; the default is the browser's language. The choice is
  kept in this browser (`diagrams.locale`); Clear everything forgets it. A choice is kept and shown only once its
  language has downloaded, and the latest choice wins; a failed download changes nothing and the dialog says so, with
  Retry. While a language downloads at startup, the view the address asks for downloads too.
- Converted so far: the start card, the top bar, the File, View and presenting controls, Share…, the shortcuts sheet,
  the Private diagram and Clear everything dialogs, the Language dialog, and the remaining File dialogs: paste,
  share links, import reports and draw.io pages, image and Interactive HTML exports (including passwords), all
  three embed sources, password links and unlock, Your diagrams, native picker descriptions, storage providers
  and their prompts and toasts; the AI panel's UI, dictation and on-device model controls; and keyboard key names,
  including the shortcuts sheet's Live and presenting rows. Key conventions are recorded in
  [`research/keyboard-key-names.md`](research/keyboard-key-names.md) and each language's glossary.
  The canvas, node, edge, boundary and annotation menus, quick-add and their submenus; edit and selection feedback;
  Ctrl+K commands, groups, hints and empty states; the stencil rail and gallery filters, categories, families,
  role explanations, details and buttons; canvas controls, empty-state instructions and the first-visit tip are
  converted too. The stencil catalog's generic names, descriptions, subtitles and non-brand vendor labels now
  translate in the library, gallery, previews, Change stencil menu, inspector stencil rows, import choices and AI
  choice rows. Product names keep their original spelling. Your diagrams already uses the File batch's translations.
  The rest of the inspector, Live/capacity, planning and Checks wording remain for later batches. Geometric edges (alignment,
  network edge and diagram perimeter) and the compound consumer-group label have glossary exceptions because
  they are not standalone diagram-connection or consumer terms.
  Agent-facing prompts, WebMCP contracts and tool results stay as written. Everything else is English until its
  batch (research § 9); a later batch converts a whole area at once.

## Standalone pages

The sign-in callback (`auth.html`) and agent-skill install page (`/skill/`) use the same compiled
`t()` messages as the app: `staticAuth.*` and `staticSkill.*` in `en.ts`, every locale JSON and
its glossary/stamps. Privacy and Terms are intentionally English-only, pending an owner decision.

`scripts/static-pages.ts` builds each `src/static/` entry to a classic script at the HTML's
existing URL. Stable `data-testid` blocks and `data-slot` children bind each translation without
depending on paragraph or list order. English rendering preserves the authored DOM and whitespace.
`i18n({ prefix })` includes only that page's messages, with the regular compiler and lookup IDs.
The app runtime catalogs exclude both standalone namespaces; validation and parity still use the
complete catalogs. All offered languages are bundled into that script, so direct links and offline/file:// copies
need no additional catalog request. The scripts share `src/i18n/preferences.ts` with the app:
saved supported choice, browser language fallback, then English (or a self-hosted build's default).
Commands and file paths keep their bytes and LTR direction. Translated sentences reorder real
DOM nodes through placeholders; catalog text never becomes HTML. Add a future page's entry to
`PAGES` and its converted source to `TRANSLATED` in `eslint.config.js`.

## Where things are

## Adding or changing a string

1. Add the message to `src/i18n/en.ts` under its area's key (`share.linkDesc`, `file.saveAs`). Keys are `area.name`,
   lower camel case. Write it in the app's vocabulary (`docs/UX-PRINCIPLES.md`).
2. Use it:

   ```tsx
   import { t, useLocale } from "../i18n";
   import { tRich } from "../i18n/rich";

   function SaveRow() {
     useLocale(); // re-render when the language changes (the App re-renders too, but memoized parts need this)
     return <span title={t("file.buttonTitle")}>{t("file.libraryCount", { count })}</span>;
   }
   // Tags: the words stay one message, so a language can move the bold part.
   tRich("share.linkDesc", { b: (chunks) => <strong>{chunks}</strong> });
   // A table built once (the shortcuts sheet): a message to translate when shown.
   const UNDO = msg("shortcuts.undo"); // …later: UNDO()
   ```

   TypeScript checks the key and the values against the English message: `{count, plural, …}` needs a number,
   `{name}` a string or number, a tag a render function; a plain message takes none.

3. Always pass the **key as a string literal**: the build rewrites `t("file.new")` to t`New diagram` (and
   `t("file.libraryCount", …)` to `t(41, v=>…, …)`). It reads each module's syntax tree and follows the imported
   bindings, so `import { t as tr }` works and a method `other.t(…)`, a local `t`, a string or a comment are left
   alone. What it can't rewrite fails the build: a computed key (for a table, use `msg` per row, as
   `src/components/ShortcutsDialog.tsx` does), `t` passed around as a value, a namespace import, and a message with
   tags through `t` or `msg` (TypeScript rejects that too: tags need `tRich` and their render functions).
4. Never build a sentence from pieces (`t("a") + name + t("b")`): one message with a placeholder, so a language can
   order it. Never put a count into a non-plural message: `{count, plural, one {# node} other {# nodes}}`, even
   where English doesn't change, because Polish, Russian and Arabic do.
5. Changing English text makes the key **stale** in every language: the old translation keeps showing, and
   `pnpm i18n check` lists it until it's translated again. Change the key instead when the meaning changes.

The message syntax is ICU-lite (`src/i18n/icu.ts`): `{name}`, `{n, number}`, `{n, number, percent}`, `plural`,
`selectordinal`, `select`, `<tag>…</tag>`, and ICU's apostrophe quoting (only before `{`, `}` or `<`, so "can't"
needs nothing).

### What never goes through t()

The person's diagram (labels, notes, titles), product and stencil brand names (Kafka, PostgreSQL), file formats and
JSON keys, WebMCP tool names, schemas and agent-facing descriptions, and the on-device model's prompts: research § 3
says why. Brand names in a converted file need a lint exception with the reason:

```ts
// eslint-disable-next-line local/no-literal-ui-text -- a product name
title: "draw.io",
```

### Converting an area (a batch)

Preserve the original English literals, interpolation, punctuation and context-specific formatting during
extraction. Compare the whole converted area against the base branch, including messages assembled from
constants or helpers. Provider names and image formats belong in full-sentence placeholders. Deliberate
copy changes need their own explanation and updated expectations; `src/i18n/englishFileMessages.test.ts`
guards the File batch's original output, alongside browser regressions for the actual call sites.

Move its strings into `en.ts`, call `t` in the files, add the files to `TRANSLATED` in `eslint.config.js` (the lint
rule then flags any word left behind), convert its CSS to logical properties (below), translate (next section), and
check it in the pseudo-locale and in Arabic.

## Translating

```sh
pnpm i18n todo de > todo.json   # what German needs: missing and stale messages, its plural forms, glossary and rules
# translate todo.json (an AI translator with the glossary, or a person), merge into src/i18n/locales/de.json
pnpm i18n stamp de              # record that these translations match today's English
pnpm i18n check de --verbose    # errors fail; warnings are for review
```

The launch translations were made this way: one AI translator per language family, given the research's glossary
tables, then validated. `pnpm i18n check` (and `src/i18n/catalogs.test.ts` in CI) fails on:

- ICU that doesn't parse; placeholders or tags that differ from English's;
- a plural missing a form the language needs (Polish one/few/many, Arabic all six) or with one it can't use;
- a protected name changed (`doNotTranslate`: Live Diagrams, Kafka, Google Drive, draw.io…);
- a glossary term rendered against the language's glossary.

It warns (never fails) on missing and stale messages, text identical to English, translations over 1.6× English's
length, and French spacing. Missing messages show in English, so English work never waits for 37 languages.

## Adding a language

```sh
pnpm i18n add ca      # src/i18n/locales/ca.json (empty), ca.meta.json, src/i18n/glossary/ca.json
```

Fill in the glossary first (research § 2 has the method: what Microsoft's terminology, the cloud vendors and the
language's developer communities use; keep English where developers do), then translate as above. The build offers
every catalog in `src/i18n/locales` automatically: the language appears in the Language dialog, is matched from the
browser, and its chunk loads only for the people who use it. A right-to-left language must be added to `isRtl` in
`src/i18n/load.ts` (Arabic, Hebrew, Persian and Urdu are there already).

## The glossary

`src/i18n/glossary/terms.json` lists each term (`topic`, `consumer group`, `boundary`, `private`, `this device`…) with
the English forms that find it in a message. Each language's file decides it:

```json
"topic": { "use": "topic", "keepEnglish": true, "avoid": ["тема"], "note": "тема is the app's colour theme" }
```

- `use`: what translations write; `match`: stems that also count (inflected forms: `диаграм` matches диаграмата);
- `avoid`: forms that must not appear; `keepEnglish`: developers in this language keep the English word;
- `except`: keys where a natural translation leaves the term out (in the shortcuts sheet, "a boundary's edge" is its
  border, not a connection).

Change a term in the glossary first, then `pnpm i18n check` shows every message that no longer follows it.

## Corrections

Every language not reviewed by a fluent person says so in the Language dialog: "Translated by machine. Something
reads wrong? Suggest a better translation on GitHub." The link opens a prefilled issue (`translation` label: the
language, where in the app, what it says, what it should say). To apply one: fix `src/i18n/locales/<code>.json` (and
the glossary, if it's a term), `pnpm i18n stamp <code> --keys key1,key2`, `pnpm i18n check <code>`. When a fluent
person has reviewed a whole language, set `"reviewed": true` in its `.meta.json`: the notice goes.

## Layout rules for translated areas

- **Room:** fit English + 40% at 1280 × 800. No fixed widths on text; let rows wrap. The pseudo-locale (`en-XA`: every
  letter accented, padded 40% longer, in brackets) is in the dev server and the e2e build: pick "English
  (Pseudo-Accents)" in the Language dialog, or set `localStorage["diagrams.locale"] = "en-XA"`. A bracket cut off is
  an overflow; text without brackets isn't translated. `tests/e2e/i18n.spec.ts` checks the converted areas.
- **Right to left:** use logical properties (`margin-inline-start`, `padding-inline`, `inset-inline-end`,
  `text-align: start`), never `left`/`right` for layout; flip arrows and chevrons that point "onward"
  (`[dir="rtl"] … { transform: scaleX(-1) }`). The diagram never mirrors: `.react-flow` keeps `direction: ltr`.
  Menus open from the trigger's other edge and their submenus to the left (`src/interop/ui/Menu.tsx`).
- **Scripts:** no web fonts beyond Mona Sans (Latin and Vietnamese); every other script uses the system's UI font,
  which the CSP allows. `<html lang>` picks the right Han glyphs; `src/styles/app.css` sets Japanese and Chinese line
  breaking, Korean `keep-all` and hyphenation for compound-heavy languages.

## Formatting

Use `src/i18n/format.ts`, never `toFixed` or string concatenation, for anything people read: `formatNumber`,
`formatPercent`, `formatRate` ("1,200 msg/s"), `formatDuration`, `formatDate`, `formatList` ("A, B und C") and
`formatAgo` ("5 min ago"; "vor 5 Min."). They read the current language. Inside a message, `{n, number}` and plural
`#` are formatted for the language too.

## Self-hosting

`VITE_LOCALES` limits the languages a copy offers, its default first (docs/SELF-HOSTING.md): `VITE_LOCALES=de,en`
offers German and English (German for browsers that ask for neither); `VITE_LOCALES=de` is German for everyone, with no
Language choice. Catalogs not offered aren't built. Unset: every language.

## Size

Stencil batch 5 keeps `src/stencils/catalog.ts` and the registry's fallback record in English. They supply stored
node defaults and agent contracts. `src/i18n/stencils.ts` contains lazy display lookups, subscribed by their UI
consumers; never import it from the registry, model or startup settings. Shared node renderers receive a
`stencilName` display prop while their `label` and `sublabel` remain the person's diagram content. All 37 catalogs
include the extracted display messages. A catalog's network "edge" means perimeter/edge computing, so those keys
have the same glossary exception as the network category description.

`src/lib/stencilSearch.ts` is the stable English search used by agents and resolution. UI consumers use
`stencilDisplaySearch.ts`, which adds translated names, subtitles, descriptions, categories, families and vendors
to English discovery. Each query token can match either language; translated names get the same ranking as English
names. The display index is cached per stencil and rebuilt after a language change. Tests compare all English
display fields with the original catalog and agent results before and after changing language; the build-split test
keeps display messages and search out of startup.

Planning P1's `planning.*` strings live in lazy explanation/model panels. Numeric/list formatters stay
lazy in `src/i18n/format.ts`; startup imports only `formatAgo` from `src/i18n/relativeTime.ts` (also
re-exported by `format.ts`). This keeps planning formatters out of the entry. P1 messages currently
fall back to English in all 37 non-English catalogs. P2's `broker.*` vocabulary and readouts are translated
in every catalog, with partition, shard, subscription and binding terminology in each glossary. Subscription
glossaries retain existing cloud-account forms alongside messaging forms. Paused live views invalidate
translated capacity copy and assignment notes when the language changes.

Planning P1's `planning.*` strings live in lazy explanation/model panels. Rate, date and list formatters stay
lazy in `src/i18n/format.ts`; canvas chrome shares `formatNumber` from the small `src/i18n/number.ts` module
(re-exported by `format.ts`). Startup imports only `formatAgo` from `src/i18n/relativeTime.ts` (also
