# Autoscaling A3 review round 1 (2026-10-16)

The seven-angle code review against origin/master (`.reviews/20261015-224032`) reported seven P1 and eleven P2
entries; several described the same defect, leaving four distinct P1 defects. Each was reproduced, fixed and given
a regression that fails with the fix reverted (checked by deliberate reversion, then restored). The nightly
5,000-seed oracle run that finished during the review is recorded at the end.

Partly taken: the architecture reviewer suggested making a fix's re-check await the worker. The re-check reads the
worker's remembered plans for exactly the current content, which are the plans its finding came from; if the
diagram changed in a way a simulation sees, there are none yet and the fix says the diagram changed, as other
stale fixes do. The suggestion to reuse one projection for the canvas's own simulation invalidation is noted in
`simulationContent.ts`: the canvas compares flow nodes in place without copying, so both list the same fields.

Nightly run (5,000 seeds per generator) during the review: 11 A3 failures, two causes. Ten were the oracle: a
resumed override above the maximum is clamped to the bound with no metric, which the ECS missing-data and Monitor
direction checks misread; the oracle now treats a clamp to the bound as the range's move. One (seed 3189) was a
sampled-memory accounting gap shared with A2: attempts admitted alongside work that kept an older, larger
concurrency weren't counted toward the retained-residence cap. Fixed in the engine, with no parity golden
change. The three minimal reproductions replay on every run (`tests/fixtures/autoscaling/a3-nightly-repros.json`).
