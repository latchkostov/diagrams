## Caching Checks UX review

The existing Checks card contains all four rules, fixes and option chips. No toolbar, menu item
or Inspector control is added, so the chrome and menu budgets do not grow. Primary actions say
One fetch per item, Serve stale while refreshing, Keep for a duration, or Add replicas.

## Honesty and language

Findings distinguish estimated reuse from the configured-rate Cold cache probe. Incomplete
probes remain visible; refused replays never certify a policy. Stampede fixes preserve freshness
and never scale into the herd. English worker/agent output stays deterministic. The UI renders
English or Arabic descriptors, isolating authored names and methods for bidirectional text.

## Review surfaces

Production-build regressions exercise keyboard application, alternative policy, undo, the compact
1024 px Arabic card and agent parity on public examples. Screenshots are collected outside the repo.
The English and Arabic screenshots were inspected: actions and names fit, the Arabic card remains
inside the 1024 px viewport, and authored Latin names stay isolated. Existing generic Checks chrome
still uses its earlier English fallback where it has not been converted; the new caching copy is Arabic.
