## Studies 4–6 UX review

The studies use the existing intro, milestone strip and finish card. They add no canvas chrome or new controls.
The initial instruction describes an outcome; Show me provides the exact inspector controls or quick-add picks.
Every finish card links to a fuller public reference design and asks what the simplified model leaves out.

Milestones judge meaningful evidence: provider rejection counts accompany successful deliveries; latency requires
completed model work; the neighbouring cell must process requests as the deployed cell fails. Outage runs use
fixed seeds and wait past their fault timelines, rather than accepting initial zero counters.

The RAG copy explicitly calls Share an assumed cache hit rate. The cell study describes separate services and
asks about storage, replication and spare capacity at the end. It does not imply that a boundary creates data
isolation or that a cache automatically learns answers.

Rejected new runner forms and app controls: existing path patches, metrics, membership and saved runs express
all nine milestones. Public reference examples already demonstrate these mechanisms; the studies do not add a
new simulation feature or alter the references.
