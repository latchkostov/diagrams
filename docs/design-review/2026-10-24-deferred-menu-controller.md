## Deferred menus and naming: UX review

The menu retains its existing entry points, actions, search ranking and keyboard navigation. No toolbar
controls are added. While rows download, the menu owns focus and shows the existing translated loading
message; Escape, click-away, wheel, resize and blur retain cancellation paths. A failed download offers
the existing Retry action inside the menu, so recovery can preserve its queued input.

The interaction controller owns the pending queue. Each key commits before the next key is delivered;
Enter can replace menu search with the existing pending-name capture. The adapter consults that newest
owner for every key, including after the picked menu unmounts. Inspector requests carry any placement
text already entered, preserving it when the node container or identity fields arrive later.

Rejected another queue local to ContextMenu or MenuList: it cannot reliably transfer ownership after
Enter. Kept the cancellable shell eager, the existing menu ordering and selection policies, and every
bundle budget. Deferred the node container only with held-container and held-identity comparisons.
This is a loading change, so no new showcase example or parity golden is needed.
