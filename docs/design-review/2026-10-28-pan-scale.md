## Pan and drag performance review

The interaction contract stays the same: middle-button and Space pans in Edit, drag-to-pan in Live and Present,
wheel and keyboard navigation, Follow, low-zoom chips and moving zone labels. No controls or chrome are added.
Native pointer capture lasts through a held pan and releases on pointer-up or cancellation. Interactive controls
and connection handles retain their own gestures. Existing off-screen DOM and accessible names remain present.

Identity fitting runs before the first entering frame paints, rather than forcing layout inside the input handler.
Regression coverage includes a held pointer and the first frame; no settling delay may conceal missing identity.
Live's virtual-cursor semantics keep refreshing off-screen values at publication time, even when no pan render runs.

## Measurement method

The production benchmark uses deterministic public pipeline workloads at 500 and 1,500 nodes, 1440×900,
Chromium at the repository's default 2× CPU throttle, three fresh contexts per case. Fitted and mostly off-screen
views are separate controls. Every gesture has 20 frame-paced steps. Inspector reveal and camera settling happen
before measuring a node's drag grip. Live runs traffic; its reported task time includes simulation/publication work.
Dragging a Live card pans the view, since editing is disabled in Live.

`tests/bench/ui/panScale.bench.ts` extends the existing interaction harness. `BENCH_PAN_TRACE=1` records separate
Chrome timeline traces and CPU profiles on the names build; traced durations are not used for before/after timings.
`BENCH_PAN_SAMPLES` defaults to three; `BENCH_PAN_LIVE=0` supports focused Edit experiments. Raw evidence is retained
under `tests/.output/pan-before` and `tests/.output/pan-retained` locally.

## Initial trace findings and rejected prototypes

At 1,500 nodes, an Edit pan's trace spent approximately 26 ms/step in hit testing, 18 in paint and 13 in layer updates;
its layout counter was zero. The dominant script samples were Zustand listener/snapshot selection, React Flow edge
position selectors and DOM queries. FrameDetail and identity fitting were smaller contributors to this held gesture.
Live added repeated badge renders/comparisons, `badgeSemantics.refresh` and DOM selector scans on translations,
alongside the simulation's normal publications. A node drag also repeatedly parsed the complete stored diagram
through `getDiagramIdentity`/`getSaveTarget`; its release triggered decoration and grow-chip geometry reads.

Whole-viewport `will-change: transform` was rejected: at 1,500 nodes it increased pan cost from roughly 76–88 to
171–172 ms/step. Promoting the node/edge layers or individual parts also regressed compared with pointer capture.
Disabling pointer events throughout the drawing did not reliably improve the 1,500-node case by 10%, and was dropped.
Pointer capture alone consistently improved the prototypes: about 41→22 ms/step at 500 and 82→57 at 1,500.

A session-metadata cache eliminated repeated JSON parses during drags but improved the first two fitted drag
samples by only 1–3% (122→119–121 ms/step). It was removed to honor the 10% improvement threshold; decoration
and grow-chip geometry at release remain the larger drag costs.
A shortcut using low-zoom chips' published wrapper sizes also failed to improve the measured node drag by 10%
and was removed. The retained changes focus on pan input and Live viewport subscriptions.

## Linux stress findings

The initial stress sweep exposed missing middle-button capture when the gesture starts on a card: React Flow's
viewport is beside its background pane. Both surfaces now qualify. Capture belongs to the stable card body,
so a lazy caption replacement cannot release it. The browser regression replaces the original caption while
the pointer is held, then checks every move and release; Space, Live and Present have the same coverage.

An Inspector collapse assertion also failed during the initial sweep. The failure screenshot showed findings
arriving above the controls during the click. The same original spec passed twice on the clean base
(80 passed, zero failed or flaky), so this is not recorded as a proven pre-existing failure. Its fixture now
waits for real background checks before targeting controls; a held-chunk regression covers that preparation.
All existing summary assertions remain. The complete canvas and Live unit folders passed: 216 files,
3,355 tests, one skipped. Initial failed and interrupted runs remain in the local evidence, separately from
the final gate summaries.

## Preserving download reserves

The first full-gate attempt passed all 3,178 parity goldens unchanged, but found the Live download reserve
510 gzip bytes over its limit and the skill zip 72 bytes over. It was stopped before the browser sweep.
Importing the visible-set comparator from the spatial-query module had pulled that module into Live's
initial closure. Keeping the comparator with badge memoization restores the lazy spatial-query boundary;
the 29 bundle-split heavy assertions then pass unchanged. The exported viewer is always read-only, so it
omits the unreachable Space/Alt authoring modifier listeners while retaining pointer capture and middle-button
autoscroll prevention. No budget, reserve or golden is changed.
