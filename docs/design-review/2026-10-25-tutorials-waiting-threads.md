## Waiting and threads tutorial UX review

The batch uses the existing tutorial strip, Simulations picker, Request context menu, inspector and hover
readouts. It adds no global controls or focus handling. Steps name the relevant control and finish with a
single lesson; watch steps leave the canvas undimmed. Request subjects resolve by stencil and connections,
so tutorial instructions do not depend on saved node ids.

The Request menu's Simulation → Free the thread while waiting action gives the thread lesson a stable
test-id path using existing controls. A proposed optional test-id mechanism in the shared segmented control
was removed because its bundle impact violated the tutorial lane's zero-byte canvas requirement.

Saved runs intentionally latch before later comparisons replace them. Property patches preserve sibling
caller settings. Timeout runs wait for observable outcomes; the free-thread observation excludes the empty
initial snapshot. Show me, Skip, Continue and selection perturbations use the existing completion contract.

Request edits explicitly return to editing before changing diagram properties, then go Live for the next
saved comparison. In a saved run those same controls edit the simulation's overrides, so changing them
there would not satisfy a lesson about diagram properties. Unlabelled Request paths are targeted directly.

Keep Backlog and lag hidden until the owner decides its Add a consumer action and test id. The current
slow-reader Trouble offers Inputs, and adding a node restarts the run; the final two steps cannot be
expressed as requested with the current action and metric forms. Keep Scale to zero hidden until the
owner defines a cold-start observation; starting replicas have not been substituted for a counter.
