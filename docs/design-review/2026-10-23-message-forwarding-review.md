## UX review

The review keeps message editing in the existing inspector and context surfaces. It adds no toolbar controls, menus or persistent chrome. Carries and choices use the same semantic analysis as focused edge details, including saved-only inputs; moving a diagram cannot make those readers recompute its typed graph.

## Keyboard and continuity

Rule removal has an explicit focus-policy event: after the edit commits, focus continues at a surviving rule or Add a rule. Both the Remove button and Unchanged use that path. Rows follow incoming-type identity and discard removed draft state. A stable callback focuses new-type inputs only when they mount. Input modality is tracked once across readers so Ctrl+Alt navigation after a pointer click also opens the edge details, even when the browser omits :focus-visible. Focused edge tooltips load on intent, remain readable at low zoom and augment the React Flow wrapper's accessible description. Escape dismisses only the current focus tooltip; refocusing the edge opens it anew. Moving focus away removes the tooltip and suspends its selector.

## Honest automatic fixes

Loop fixes retain their existing one-step action and Undo. Candidates preserve every non-loop path in each configured run; a new cyclic transition anywhere rejects a candidate. Exhausting the shared optional verification budget leaves the warning and manual guidance visible. Simulations with runtime property edits receive manual guidance because this static verifier cannot prove their temporal behavior.

## Rejected approaches

A lower SCC count cannot prove safety: two loops can merge. Array identities cannot describe routing content: dragging changes arrays. Truncating authored types would merge distinct names. Increasing test timeouts would conceal the dev-server interception hang. Raising bundle budgets would conceal dependency costs; request matching instead joins the shared pure forwarding decision, and the tooltip loads with carried types.

## Validation

Targeted regressions cover playback/capacity agreement, saved traffic and setup preservation, rename rejection, position-only call counts, bounded verification and long names. Reverting the implementations to the review head reproduces ten unit failures and all five loading/focus regressions. Final repeated browser checks and parity are recorded in the release verification report.
