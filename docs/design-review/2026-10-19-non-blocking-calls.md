## Requests that free threads

Reviewed the blocking and freed caller screenshots from the production browser regression and
the new inspector/menu flows against the UX principles. The meter remains on the card; the
connection pill stays in the gap between cards. Hatching and the hourglass distinguish held
threads, and the arrow plus words distinguish calls in flight without relying on colour.

There are no new toolbar controls. While waiting is in the connection's Simulation disclosure;
reply handling and the optional Connection pool are in Advanced. The right-click uses one
Simulation submenu with one toggle. Labels use the existing Request vocabulary and translated
English keys. The meter's accessible value text describes off-thread calls.

The exhausted-thread callout has one primary action, disabled during slow motion. It edits one
connection in one undo step and names the dependency. Recent saturation samples prevent the fix
from vanishing during the ordinary gap between a reply and new admission. The freed hover shows
work plus reply handling in its Ceiling arithmetic and explains that waiting calls still use memory.

The example compares the same generic system and CPU rule across both runs. It shows the benefit
before ten seconds and saves the CPU-scaling lesson for the spike. New deadlines, pool-wait UI,
busy-thread metrics and Checks were rejected here because they belong to PRs 3–5.

Lazy loading keeps Advanced editing and secondary Live panels out of the first-view download.
The existing action ids, focus/placement hooks and data-testid contracts are preserved; the browser
gate exercises the affected menus and neighbouring inspector/viewport flows under load.
