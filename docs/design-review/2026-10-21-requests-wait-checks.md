## Requests that wait: Checks and agents parity

The Checks row keeps one primary action, chosen by the same verified selector as the live callout.
Alternatives stay in its existing option-chip row; no bar, menu or inspector controls were added. Top-bar
and floating-bar budgets are unchanged. The new busy/waiting metrics are options in the existing expectation
picker and use its existing chips. Timeout information uses the existing suggestion tier.

The replica alternative explicitly names a fixed fleet because it disables the old autoscaler. Existing
resource and invalid-policy warnings retain precedence; only redundant busy-thread scenario findings are
replaced. A successful fix clears its warning, and Undo restores it. Keyboard option activation uses the
original option identity even when the visible label is translated. Focus follows the existing neighbour
policy, and the busy-thread primary keeps the selected service and its changed target in Properties.

The timeout Check shares the callout's affordable value and offers no unverified value when none fits.
Checks still diagnose normal configured rates; an intentionally failing saved drill is explained in Live.
The public CPU-scaling and payment lessons retain their gallery order and Requests that wait tags.
English, Arabic and pseudo-locale keyboard paths are covered by the new browser spec.
