## Markdown rendering and node documentation UX review (2026-10-18)

- **Simple by default, customizable on demand**: Canvas text and note annotations render formatted Markdown in place and edit raw Markdown on double-click or `F2`, adding zero extra chrome or toolbar clutter to the canvas.
- **Subtle node documentation badge & tooltip preview**: Nodes with non-empty documentation display a quiet top-right note icon (`doc-badge-<id>`) inside the card boundary that brightens on hover or selection. Hovering or keyboard-focusing a documented node previews its formatted Markdown inside `NodeTooltip` (`node-tooltip-doc`), and clicking the badge selects the node and opens the Inspector even if the Inspector was previously folded. In Present mode, the badge remains visible and hovering nodes previews the formatted documentation for audience walkthroughs, while in Live mode the badge is cleanly hidden so simulations stay focused on runtime telemetry and queue metrics without editing affordances.
- **Preview-first Inspector editing**: In the Inspector (`DiagramPanel`, `AnnotationPanel`, and `NodePanel`), `MarkdownEditor` defaults to `Preview` mode when documentation is present so reading runbooks, SLO tables, and links is immediate, while defaulting to `Edit` mode when empty so typing can start with a single click.
- **Native text-field ergonomics preserved**: By keeping the underlying `<textarea>` mounted in the same CSS grid cell beneath the preview layer, a single click switches cleanly to `Edit` mode while native double-click word selection and triple-click line selection continue to work identically across light and dark themes.
- **Keyboard shortcut isolation**: `Ctrl/Cmd+K` inside a Markdown field inserts a `[text](url)` link (and stops propagation so the global Command Palette does not intercept it), while `Escape` returns from `Edit` to `Preview` mode.
